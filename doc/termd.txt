*termd.txt*  Read Markdown with termd, in a Neovim window

==============================================================================
INTRODUCTION                                                           *termd*

Shows the current Markdown buffer as a rendered page, drawn by termd
(https://github.com/yangtau/termd), laid over the buffer's own window: page
and source take turns there (|termd-reader|).

  - It shows the buffer as it is, unsaved changes included.
  - It follows the cursor and the source window (|termd-scrolling|).
  - termd stops when the buffer is deleted, with |:TermdClose|, or when
    Neovim exits.

Requirements:

  - A terminal with Kitty Unicode placeholders: kitty 0.28 or newer, or
    Ghostty. WezTerm does not have them.
  - 'termguicolors'.
  - Inside tmux: `set -g allow-passthrough on`, and kitty or Ghostty
    outside of it.
  - Neovim 0.9 or newer, and a termd that has `--serve`.

Images reach a terminal on the same machine through shared memory (kitty)
or temporary files (others), so only short escape sequences are written to
it. Over SSH the pixels have to go inline; as Neovim's UI writes to the same
terminal at the same time, a busy screen can then end up with stray
characters or a missing piece. CTRL-L draws it again.

==============================================================================
COMMANDS                                                      *termd-commands*

:TermdRead                                                        *:TermdRead*
    Read the current buffer: lay the page over its window, following the
    cursor, until `q` or editing (|termd-reader|). <Esc> in Normal mode does
    the same in a Markdown buffer (`read_key`).

:TermdClose                                                      *:TermdClose*
    Stop reading the current buffer, and stop termd; `read_key` no longer
    reads in this buffer until |:TermdRead|.

The same from Lua: `require("termd").read()`, `.close()`; each takes an
optional buffer number. `.unread()` stops reading and leaves termd running;
`.reading()` tells whether the page lies over the current window (or the
one given); `.is_open()` whether termd runs for the buffer.

==============================================================================
SETUP                                                            *termd-setup*

Calling setup() is optional. The defaults: >lua

    require("termd").setup({
      cmd = "termd",        -- the executable
      args = {},            -- extra arguments, e.g. { "--sans", "--zoom", "0.9" }
      smooth = 120,         -- ms the page takes to catch up; 0 jumps
      cell_size = nil,      -- { w, h } pixels, if the terminal does not say
      reader = true,        -- open Markdown files reading (|termd-reader|)
      read_key = "<Esc>",   -- key in Normal mode that reads; false for none
    })
<
With lazy.nvim: >lua

    {
      "yangtau/termd",
      ft = "markdown",      -- for `reader`: loaded when a Markdown file opens
      cmd = { "TermdRead", "TermdClose" },
      opts = {},
    }
<
The text is about the size of the terminal's own (0.85 of a line's
height); `--zoom` in `args` changes that. The page's buffer has 'filetype' `termd`.

==============================================================================
SCROLLING                                                    *termd-scrolling*

The page follows the source window, not only the cursor. The lines the
source window shows are a stretch of the page, as a rule a longer one than
the window is high. With the cursor on the first row of the source window
page and source start with the same text, with the cursor on the last row
both end with it, and in between the page slides from the one to the other.
So the cursor's line is at about the same height in both, a step of the
cursor moves the page by the same small amount whatever the line looks like
on the page, and scrolling the source window (CTRL-E, the mouse wheel)
scrolls the page too. The place the cursor is at always shows.

When the page has more than a row to go it scrolls there over a few frames
(`smooth`, in milliseconds; 0 turns that off). A long jump (gg, a search)
shows only the last screenful of the way.

==============================================================================
READER                                                          *termd-reader*

Reading is a mode of its own for a Markdown buffer, one level out from
Normal mode: <Esc> in Normal mode reads (so <Esc> twice from Insert mode),
and |:TermdRead| does too. The page then lies over the source's window,
which keeps the buffer and the focus: move the cursor and scroll as in the
source (j, CTRL-D, gg, /, n, the mouse wheel) and the page follows
(|termd-scrolling|). The page shows the cursor on the character it is on;
on markup that the page does not show (`**`, a link's address, `# `) as a
caret by the nearest text of its line, and on an empty line as a caret
between the blocks around it. With 'hlsearch' the matches of the last
search are lit up on the page too, the one at the cursor more than the
others, until |:nohlsearch|. (With a termd older than the plugin a bar at
the left edge marks the cursor's line instead.)
<Esc> does nothing more, so pressing it once too often stays put. The source shows again, its cursor where it was,
with:

    q <CR>          Stop reading.
    i a o v d c     Anything that leaves Normal mode for another mode than
    ...             the command line (Insert, Visual, an operator), or
                    changes the text (x, p, u, :s): you are editing.

`:w`, searches and other commands on the command line keep reading. As the
window still has the file, whatever goes by the current buffer finds it: a
file tree (neo-tree reveals the file), the status line, `:w`, CTRL-^.

termd keeps running in between, so the page comes back at once
(|:TermdClose| stops it, and <Esc> reads again only after |:TermdRead|).
<Esc> reads only in a plain window: not in a diff, in a floating window or
while a macro runs. Set `read_key` to another key, or to false to read only with |:TermdRead|;
with another key <Esc> also stops reading.

With `reader` (the default) a Markdown file opens reading, the first time
it shows: a file left for its source stays so when you come back to it. Set
`reader = false` to open files as source. The plugin has to be loaded for
`reader` and `read_key` to do anything: with lazy.nvim, add
`ft = "markdown"` to its spec.

Neovim has no way to add a mode of its own, so the mode indicator still
says NORMAL. A status line can show reading with
`require("termd").reading()`, true for a window the page lies over. The
terminal's cursor is hidden there (|guicursor| `n` and `r`, with a
highlight of `blend` 100: Neovim 0.12 gives a cursor behind a floating
window the shape of Replace mode).

The colors come from highlight groups, their background or else their
text color, mixed with the background:

    TermdCursor     the cursor (links to Title)
    TermdSearch     search matches (links to Search)
    TermdCurSearch  the match at the cursor (links to CurSearch)

==============================================================================
HOW IT WORKS                                                       *termd-how*

The page's buffer is filled with Kitty Unicode placeholders: U+10EEEE with
combining marks that number a row and a column of an image. The terminal
draws the image there instead of text, picking it by the cell's foreground
color. So Neovim scrolls and redraws the page like any other text.

`termd --serve FILE` lays out the page at the window's width (FILE only says
where links and images are found) and renders it in chunks of rows, each an
image of its own. The plugin sends it the buffer's text and the rows the
window shows; termd answers with the escape sequences for the chunks in and
near view, which the plugin writes to the terminal. With every page comes a
map of the row each source line is at, which the plugin scrolls by. See
src/serve.rs for the protocol. Plugin and termd have to be of the same version.

Run |:checkhealth| termd when something does not work.
