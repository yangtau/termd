# termd

在终端里以「渲染后的页面」预览 Markdown：把文档按像素排版成图像，通过
[Kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/) 显示，并支持像素级滚动。

和 `glow`、`mdcat` 这类字符渲染不同，termd 画的是真正的排版结果：比例字体、不同字号的标题、
圆角代码块、表格、内嵌图片。

页面没有自己的底色：没有画东西的地方是透明的，直接透出终端的背景，文字颜色也取自终端，
所以不管用什么配色方案都不会出现一块突兀的白底或黑底。

## 使用

```sh
cargo install --path .
termd README.md
```

也可以用 Nix。CI 会把 Linux x86_64 和 macOS arm64 的构建结果推送到
[tau.cachix.org](https://tau.cachix.org)，所以通常是直接下载，不需要本地编译：

```sh
nix run github:yangtau/termd -- README.md            # main 上的最新版本
nix run github:yangtau/termd/v0.2.0 -- README.md     # 指定版本（git 标签）
nix profile install github:yangtau/termd/v0.2.0
```

flake 里已经声明了缓存地址和公钥（`nixConfig`），第一次使用时 Nix 会询问是否信任，
也可以加 `--accept-flake-config`。如果你的用户不在 Nix 的 `trusted-users` 里，
需要把缓存加到系统的 `nix.conf`：

```
extra-substituters = https://tau.cachix.org
extra-trusted-public-keys = tau.cachix.org-1:tqAThmpvqthNsfMUwRlljsDKPW8147I/+yzRVZnxKsA=
```

在自己的 flake 里使用：

```nix
inputs.termd.url = "github:yangtau/termd/v0.2.0";   # 不写标签就是 main
environment.systemPackages = [ inputs.termd.packages.${pkgs.system}.default ];
# 或者 overlay：nixpkgs.overlays = [ inputs.termd.overlays.default ]; 之后用 pkgs.termd
```

需要支持 Kitty 图像协议的终端（kitty、Ghostty、WezTerm 等）。暂不支持在 tmux 内运行。

| 按键 | 动作 |
|:-----|:-----|
| `j` / `k`、`↓` / `↑`、鼠标滚轮 | 上下滚动 |
| `space` / `b`、`PgDn` / `PgUp` | 翻页 |
| `d` / `u` | 半页 |
| `g` / `G` | 顶部 / 底部 |
| `+` / `-` / `0` | 放大 / 缩小 / 还原 |
| `e` | 用 `$VISUAL` / `$EDITOR` 打开文件，光标在视口顶部对应的源码行；退出编辑器后回到原来的位置 |
| `y` / `Y` | 复制视口里的代码块（`Y` 连同围栏一起）；连按会依次轮到视口里的下一个代码块 |
| 点击链接 | 用系统默认方式打开；`#标题` 形式的链接跳到文内对应标题；鼠标悬停时状态栏显示目标地址 |
| 点击代码块右上角的复制图标 | 复制这个代码块 |
| 鼠标拖拽 | 选中文字，松开即复制为纯文本（列表带标记，表格单元格用制表符分隔）；拖到上下边缘会自动滚动 |
| 双击 / 三击 | 选中一个词 / 整段 |
| `Shift` + 点击 | 把选区延伸到点击处 |

| `h` / `l`、`←` / `→`、`Shift` + 滚轮、横向滚轮 | 横向滚动放不下的宽表格（鼠标所在的那张，否则是视口里的第一张） |
| `r` | 重新加载（文件变化时也会自动重载） |
| `q` / `Esc` | 退出 |

复制走的是终端的 OSC 52，所以通过 SSH 使用时也能复制到本机剪贴板。

常用选项：

- `--theme auto|dark|light`：默认 `auto`，沿用终端的前景 / 背景色，页面背景透明。
  强制指定的明暗和终端实际背景相反时，才会画一块不透明的页面底色。
  文字边缘和代码块之类的浅色底是 termd 自己按终端报告的背景色混合好的（原因见「实现」），
  所以终端设置了半透明或背景图时，这些地方会是不透明的纯色。
- `--font NAME`、`--mono-font NAME`：指定正文和代码字体。正文默认用衬线字体
  （macOS 上是 Charter + 宋体，Linux 上问 fontconfig），中文字体按 `LANG` 选简体 / 繁体 / 日文 / 韩文字形。
- `--sans`：正文改用系统界面的无衬线字体（macOS 上是 SF + PingFang）。
- `--zoom 1.2`：初始缩放。不缩放时正文字号等于终端的行高，比终端自己的字略大一点
  （比例字体，尤其是衬线字体，太小了不好看）。
- `--no-smooth-scroll`：滚动时直接跳到目标位置，不做动画（比如通过很慢的 SSH 连接使用时）。
- `--export out.png [--width 1200] [--font-size 16]`：不进入交互界面，直接把整页导出为 PNG。
- `--serve`：给编辑器插件用（见下一节）。不打开自己的界面，从 stdin 读命令、把图像通过 stdout 交给编辑器，
  由编辑器转发给终端。协议见 `src/serve.rs`。

## Neovim 插件

仓库本身就是一个 Neovim 插件（Neovim 0.9+）。页面显示在 Neovim 的窗口里，有两种用法：

**分屏预览**：`:TermdOpen` / `:TermdClose` / `:TermdToggle` 在当前窗口旁边分出一个窗口显示渲染好的页面。

- 预览窗口是普通的 Neovim 窗口：可以用 `<C-d>`、`gg`、鼠标滚轮滚动，可以调整大小、换位置、放进新的标签页；
- 预览的是缓冲区当前的内容，没保存的修改边打边更新；
- 预览跟着源码窗口滚动（见下面「滚动」）；
- 在预览窗口里按 `<CR>`（或 `e`、双击），源码窗口的光标跳到预览光标所在的那个字上；按 `q` 关闭；
- 删除缓冲区、关掉预览窗口或退出 Neovim 时，预览自动关闭。

**阅读模式**：比 Normal 再「退出一层」的状态。在 Markdown 缓冲区的 Normal 模式下按 `<Esc>`
（也就是从 Insert 模式按两下 `<Esc>`）或 `:TermdRead`，页面就盖在源码窗口上；打开 Markdown 文件时默认也直接进入
（`reader = false` 关闭）。

- 页面是一个盖在源码窗口上、不能进入的浮动窗口，窗口里的缓冲区和焦点仍是源码：
  像平常一样移动光标、滚动（`j`、`<C-d>`、`gg`、`/`、`n`、鼠标滚轮），页面跟着走，
  页面左边缘的标记是光标所在的那一行；再按 `<Esc>` 不会有反应；
- 因为当前缓冲区还是文件本身，neo-tree 能定位到文件，状态栏、`:w`、`<C-^>` 也都照常；
- `q` / `<CR>`：退出阅读；
- 编辑就会退出阅读：进入 Insert、Visual、操作符（`d`、`c`、`y`…）或者文本发生变化（`x`、`p`、`u`、`:s`）；
  `:w`、搜索这类命令行操作不会退出；
- 进出阅读时 termd 一直在后台运行，所以重新进入是即时的（`:TermdClose` 才会停掉它，
  之后 `<Esc>` 不再进入阅读，直到再次 `:TermdRead`）；
- 有分屏预览（`:TermdOpen`）、diff、浮动窗口或正在执行宏时，`<Esc>` 保持原样；
  `read_key` 可以换成别的键，设为 `false` 则只用 `:TermdRead`；
- 自动进入只在文件第一次显示时发生：退出阅读后切走再切回来，仍然是源码；
- Neovim 不支持自定义模式，状态栏的模式仍显示 NORMAL；状态栏可以用 `require("termd").reading()`
  判断当前窗口是否在阅读。阅读时终端光标在 Normal 模式下隐藏，标记的颜色是 `TermdCursor` 高亮组。

滚动：预览跟随的是源码窗口，而不只是光标所在的行。源码窗口里显示的那些行对应页面上的一段，
这一段通常比预览窗口高；光标在源码窗口第一行时两个窗口的开头对齐，在最后一行时结尾对齐，
中间按比例滑动。这样光标所在行在两边的高度大致相同，光标每走一行预览移动的量都差不多
（不管那一行在页面上是空行还是大标题），不会来回跳；滚动源码窗口（`<C-e>`、鼠标滚轮）预览也跟着滚。
预览要移动超过一行时用几帧滚过去（`smooth`，单位毫秒，设为 0 则直接跳）。

原理：预览缓冲区里填的是 Kitty 图像协议的 Unicode 占位符（U+10EEEE 加上表示行号、列号的组合字符），
终端把这些字符格换成图像的对应部分，用哪张图由字符的前景色决定。滚动、重绘都由 Neovim 自己完成，
termd（`--serve`）只负责排版、按需渲染进入视野的那几块，再把图像交给插件写给终端。
每次排版，termd 还会给出一张「源码每一行在页面第几行」的表，插件靠它在本地计算滚动位置。
插件和 termd 要用同一个版本。

要求：

- 终端支持 Unicode 占位符：kitty（0.28+）、Ghostty。WezTerm 不支持。
- `termguicolors` 打开（图像是用前景色区分的）。
- tmux 里需要 `set -g allow-passthrough on`，外层终端同样得是 kitty 或 Ghostty。
- 图像在本机通过共享内存（kitty）或临时文件（其他终端）传给终端，写进终端的只是很短的转义序列。
通过 SSH 时只能把像素内嵌在转义序列里，由于 Neovim 的界面进程同时也在往终端写，屏幕更新很频繁时
  偶尔会出现乱码或缺块，按 `<C-l>` 重绘即可。

用 lazy.nvim 安装：

```lua
{
  "yangtau/termd",
  ft = "markdown",       -- 阅读模式需要：打开 Markdown 文件时就加载插件
  cmd = { "TermdOpen", "TermdRead", "TermdClose", "TermdToggle" },
  keys = { { "<leader>mp", "<cmd>TermdToggle<cr>", desc = "Markdown preview" } },
  opts = {
    -- 下面都是默认值
    cmd = "termd",        -- termd 可执行文件
    args = {},            -- 额外参数，比如 { "--sans", "--zoom", "0.9" }
    position = "right",   -- right / left / bottom / top / tab
    size = nil,           -- 窗口宽度（上下分屏时是高度），单位是字符格；默认占一半
    focus = false,        -- 打开后焦点是否移到预览窗口
    live = true,          -- 预览未保存的修改
    follow = true,        -- 跟随源码窗口滚动
    smooth = 120,         -- 预览滚到位用的毫秒数；0 表示直接跳
    debounce = 100,       -- 停止输入多少毫秒后更新
    cell_size = nil,      -- 终端没报告字符格像素尺寸时手动指定，如 { 10, 21 }
    reader = true,        -- 打开 Markdown 文件时进入阅读模式
    read_key = "<Esc>",   -- Normal 模式下进入阅读的键；false 表示不设
  },
}
```

完整说明见 `:help termd`，出问题时可以运行 `:checkhealth termd`。

## 支持的语法

标题、段落、粗体 / 斜体 / 删除线、行内代码、链接（着色加下划线）、有序 / 无序 / 任务列表、引用、
代码块（语法高亮）、表格（含对齐，见下）、分隔线、本地图片（PNG / JPEG / GIF / WebP / BMP）、
YAML front matter（显示为页首的属性表）。
[`examples/demo.md`](examples/demo.md) 把这些格式连同各种嵌套都用了一遍，调整排版时可以拿它对照。

表格放不下时依次这样处理：先突破正文栏、最宽用到整个终端宽度；还放不下就让单元格折行
（短词的列保持原宽，长文本的列折行）；每列都缩到最窄仍然放不下，才保持舒适的列宽并横向滚动。
表格比一屏长时，表头会停在视口顶部。

暂未支持：远程图片、数学公式、脚注、文内搜索。

## 实现

文档先被排成一张固定宽度的长页面，再按 512px 高的水平分块光栅化成 RGBA 像素，
通过 Kitty 图像协议上传给终端。中间不经过 PNG 之类的图片编码。

- `src/doc.rs`：`pulldown-cmark` 解析，`cosmic-text` 排版，`tiny-skia` 画形状，字形直接贴到像素缓冲上。
  排版是增量的：只排到需要显示的位置就可以出图，剩下的在空闲时继续，所以打开一个很长的文档和打开一个短文档一样快。
  页面图像只覆盖正文那一栏而不是整个终端宽度，两侧的空白不需要传输。
- `src/fonts.rs`：字体选择。只把选中的正文、界面、等宽字体和它们各自搭配的中文字体交给排版引擎，
  并且每段文字都指定一个该字体确实存在的字重。这样既保证中文粗体不会被替换成别的字体，
  也避免了排版引擎为了找后备字体反复打开所有已安装的字体文件。文档里出现这些字体没有的字符（emoji、其他文字）时才按需补充。
- `src/coretext.rs`：macOS 上字体在哪个文件里、某个字符该用哪个后备字体，都直接问系统（Core Text）。
  系统自己维护着字体索引，问一次不到一毫秒，所以 termd 在 macOS 上既不扫描字体目录，也没有缓存，
  启动时只打开真正用到的那几个字体文件。
- `src/font_cache.rs`：其他系统上没有这样的接口，需要自己建立系统字体的索引，也就是打开机器上的每一个字体文件，
  字体多的时候要几百毫秒。索引会保存到 `~/.cache/termd/fonts`，同时记下各字体目录的修改时间；
  安装或删除字体后目录的修改时间会变，下次启动就自动重新扫描。删掉这个文件也可以强制重新扫描。
- `src/highlight.rs`：`syntect` 语法高亮，在后台线程进行。某种语言第一次高亮要编译语法定义（shell 大约 45ms），
  比显示首屏需要的其他所有工作都慢，所以代码块先以纯色显示，高亮结果出来后再把颜色补上。
  配色是自带的一套（注释、关键字、函数、字符串、数字、类型各一种颜色，明暗各一组），其余代码用正文颜色。
- `src/viewer.rs`：查看器。每个分块只上传一次；滚动时只发送「显示某块的某个区域」的放置指令，不需要重新传图，
  所以可以每 8ms 发一帧来做平滑滚动。每帧最多光栅化一个新分块，视口附近的分块在空闲时预先上传。
- `src/source.rs`：页面和源码之间的映射。每段文字都记着自己来自源码的哪一段，所以像素能对应到源码行
  （按 `e` 打开编辑器）、选区能对应到 Markdown 源码、缩放或重载后能回到原来读到的地方。
- 发给终端的像素要么完全不透明，要么完全透明：文字的抗锯齿边缘、代码块和表头的浅色底，都由 termd
  按终端报告的背景色混合好再发出去。半透明像素交给终端去混合的话，结果取决于终端的实现
  （有的在线性空间里混合，深色字会变细变淡；有的混合出来比两种颜色都深），同一页在不同终端里观感差别很大。
  只有探测不到终端背景色时才发送真正的半透明像素。
- 选区高亮因此不能垫在页面下面，而是每个分块的第二个版本：同样的内容画在选区颜色上。
  有选区时，把这个版本按选区的矩形裁出来叠在页面上面；选区变化时只需要发几十字节的放置指令，
  每个分块的高亮版本只在第一次被选到时光栅化、上传一次。
  鼠标位置在终端支持时按像素上报（SGR-Pixels，1016），否则退回到按字符格。
- 页面分块各自只覆盖自己那一段实际用到的宽度：通常是正文栏，有宽表格的分块才更宽。
  横向滚动的表格渲染成单独的图像，滚动时只改变放置指令里的裁剪位置；吸顶的表头是把同一张图的表头部分
  再放置一次（叠在最上层，下面垫一块背景色），都不需要重新上传像素。
- `src/kitty.rs`：协议编码。终端和 termd 在同一台机器上并且支持时，像素通过 POSIX 共享内存传给终端
  （启动时探测，kitty 支持）；否则用 zlib 压缩 + base64 内嵌在转义序列里（比如通过 SSH）。
- `src/serve.rs`：给编辑器插件用的渲染模式（`--serve`）。整页按约 512px 高、行数为整数的块渲染，
  每块是一张图，编辑器窗口里显示到哪些行就渲染、上传哪些块，离得远的块会从终端里释放。
- `src/term.rs`：启动时探测终端的前景 / 背景色、图像协议支持、共享内存支持和窗口像素尺寸。
- `src/theme.rs`：配色，全部由终端的前景色和背景色混合得到。

字号取自终端字符格的像素高度（正文字号等于行高），因此在 HiDPI 屏幕上会自动保持清晰。

排查启动慢的问题时可以设置 `TERMD_DEBUG=1`，退出后会在 stderr 打印启动各阶段的耗时、
选中的字体和使用的传输方式：

```sh
TERMD_DEBUG=1 termd README.md
```

## 开发与发布

`nix develop` 进入带 Rust 工具链的开发环境。

`.github/workflows/nix.yml` 在每次推送到 main、推送 `v*` 标签和 PR 时，在 Linux x86_64 和
macOS arm64 上执行 `nix build`，并把结果推送到 Cachix（需要仓库 secret `CACHIX_AUTH_TOKEN`）。

发布新版本：改 `Cargo.toml` 里的 `version`，提交到 main，然后打同名标签：

```sh
git tag v0.2.0 && git push origin v0.2.0
```

Nix 的构建结果只取决于源码，所以标签指向的提交只要在 main 上构建过，就已经在缓存里了。
